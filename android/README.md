# Money apk — Android-клиент

Тонкий клиент на Kotlin + Jetpack Compose. Вся бизнес-логика — на бэкенде (`../backend`), приложение только показывает данные и ходит в API. В проде — по HTTPS; во время разработки, пока бэкенд не задеплоен на VPS, — по обычному HTTP на локальный компьютер (см. "Как протестировать логин" ниже).

Текущий статус: **шаг 2 фазы 4** — экран логина и сетевой слой (Retrofit) поверх каркаса из шага 1. Есть вход по email/паролю, сохранение JWT-токена в зашифрованном хранилище и выход.

## Версии (актуальны на момент написания, август 2026)

- Android Gradle Plugin 9.3.0
- Gradle 9.5.0 (будет предложен автоматически, см. ниже)
- Kotlin 2.4.0
- Jetpack Compose BOM 2026.08.00
- compileSdk / targetSdk = 37, minSdk = 26 (Compose 1.12.0 требует compileSdk 37+, см. "Если что-то не собралось" ниже)
- Retrofit 3.0.0 + OkHttp logging-interceptor 5.3.2 — поход в API
- androidx.security:security-crypto 1.1.0 — шифрованное хранилище JWT-токена (EncryptedSharedPreferences; Google в 2025 пометил класс как deprecated, но он по-прежнему работает и остаётся разумным выбором для личного приложения)
- androidx.lifecycle 2.11.0 (runtime-ktx + viewmodel-compose)

## Как открыть проект в Android Studio

1. Android Studio → **File → Open** → выбрать папку `money-apk/android` (не `money-apk` целиком, а именно `android/` внутри неё).
2. В проекте **нет закоммиченного Gradle wrapper** (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`) — это сделано намеренно: эти файлы либо бинарные, либо должны точно соответствовать версии Android Studio, которая их будет использовать, поэтому надёжнее дать самой Android Studio создать их при первом открытии. Если появится диалог вида **"Gradle wrapper is not found. Create Gradle wrapper?"** — нажимайте **OK/Yes**, Android Studio сама подберёт совместимую версию Gradle.
3. Дождитесь **Gradle Sync** (внизу справа — прогресс-бар). Первый sync скачивает Gradle, Android SDK-компоненты и зависимости — может занять несколько минут, нужен интернет.
4. Если Android Studio попросит принять лицензии SDK (Android SDK licenses) — согласиться.
5. Если появится баннер про недостающие SDK-платформы/build-tools — нажать **Install missing SDK package(s)**.

## Как протестировать логин (важно — без этого экран логина не заработает)

Пока бэкенд не задеплоен на VPS, приложение на этапе разработки ходит на локальный компьютер, а не на интернет-сервер. Перед тем как нажимать "Войти" в приложении:

1. Запусти бэкенд — либо кнопкой ▶ Run в PyCharm на файле `backend/run.py`, либо в терминале (см. `../backend/README.md`):
   ```
   cd backend
   source .venv/bin/activate   # если используешь venv
   uvicorn app.main:app --reload --host 0.0.0.0
   ```
   Флаг `--host 0.0.0.0` (вместо значения по умолчанию `127.0.0.1`) заставляет сервер слушать все сетевые интерфейсы, а не только loopback. `backend/run.py` уже настроен так по умолчанию, в терминале это нужно указать явно.

   Проверить, что поднялся: `curl http://127.0.0.1:8000/health`.
2. Убедись, что пользователь засеян (`python -m app.seed` из `backend/README.md`) — вводить в приложении нужно именно `ADMIN_EMAIL`/`ADMIN_PASSWORD` из `backend/.env`.
3. Запускай Android-приложение **только на эмуляторе** (не на реальном Galaxy S25). Приложение обращается к `127.0.0.1:8000` — на эмуляторе это означает "сам эмулятор", а не хост-машину, поэтому нужен ещё один шаг: пробросить порт с эмулятора на компьютер через ADB. После того как эмулятор запущен, выполни в терминале (один раз на сессию эмулятора — до его перезапуска):
   ```
   adb reverse tcp:8000 tcp:8000
   ```
   Эта команда говорит эмулятору: "когда что-то внутри тебя обращается к `127.0.0.1:8000`, на самом деле отправляй это на порт 8000 компьютера". Работает через тот же ADB-канал, что и обычная отладка приложения, поэтому не зависит от VPN или файрвола на компьютере — в отличие от специального адреса `10.0.2.2`, который эмулятор обычно даёт для доступа к хосту напрямую по сети, но который может ломаться из-за VPN/файрвола на компьютере разработчика.

   Если `adb` не находится в терминале — это часть Android SDK (обычно `~/Library/Android/sdk/platform-tools/adb` на Mac); можно вызвать по полному пути или добавить эту папку в PATH.
4. Введи email/пароль из шага 2 и нажми "Войти".

Если что-то пошло не так — вкладка **Logcat** в Android Studio покажет полный текст запроса и ответа (мы специально включили подробное логирование сети на время разработки).

## Как запустить

- **На эмуляторе (нужен для тестирования логина, см. выше):** Android Studio → **Device Manager** → создать виртуальное устройство (любой профиль, например Pixel, с системным образом Android 14+) → выбрать его в выпадающем списке устройств вверху → зелёная кнопка ▶ **Run**.
- **На реальном Samsung Galaxy S25** (пока без рабочего логина — см. выше):
  1. На телефоне: **Настройки → О телефоне → Номер сборки** — нажать 7 раз, чтобы включить «Режим разработчика».
  2. **Настройки → Параметры разработчика → Отладка по USB** — включить.
  3. Подключить телефон к Mac по USB-кабелю, на телефоне подтвердить «Разрешить отладку по USB» во всплывающем окне.
  4. В Android Studio телефон появится в списке устройств вверху — выбрать его → ▶ **Run**.

Ожидаемый результат: сначала экран логина ("Вход в Money apk" + два поля + кнопка "Войти"), после успешного входа — экран "Money apk" / "Вход выполнен..." с кнопкой "Выйти" (сбрасывает сохранённый токен и возвращает на экран логина — удобно для повторного тестирования).

## Если что-то не собралось

Скопировать полный текст ошибки из вкладки **Build** (внизу Android Studio) и прислать — версии в этом README подобраны как актуальные на момент написания, но если Android Studio предложит более новые (это нормально — экосистема Android обновляется постоянно), можно либо согласиться на автообновление через Android Studio, либо прислать текст предложения, и версии в `gradle/libs.versions.toml` будут скорректированы.

## Структура

```
android/
  app/
    src/main/java/com/pslab/moneyapk/
      MainActivity.kt           — точка входа; решает, показать LoginScreen или WelcomeScreen
      network/
        ApiConfig.kt             — адрес бэкенда (сейчас — локальный dev-сервер через 127.0.0.1 + adb reverse)
        AuthDto.kt                — классы, повторяющие форму JSON-ответов бэкенда
        AuthApi.kt                 — Retrofit-интерфейс: POST /api/v1/auth/login
        RetrofitClient.kt          — единая точка создания Retrofit/OkHttp
      data/
        TokenStore.kt              — зашифрованное хранилище JWT-токена
      ui/
        login/
          LoginViewModel.kt         — состояние экрана логина, вызов API
          LoginScreen.kt             — Compose-разметка экрана логина
        theme/                      — тема Material3 (цвета, типографика)
    src/main/res/
      xml/network_security_config.xml — разрешает обычный HTTP только на 127.0.0.1 (dev)
    build.gradle.kts            — конфигурация модуля app
  build.gradle.kts              — корневой файл (подключение плагинов)
  settings.gradle.kts           — состав модулей
  gradle/libs.versions.toml     — версии зависимостей (version catalog)
  phase4-step1-explained.md     — подробный разбор шага 1 (для обучения)
```
