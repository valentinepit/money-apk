# Money apk — план

## Решения по архитектуре (зафиксировано)

- **Регион и валюта: сервис рассчитан на территорию ЕС, валюта — евро (EUR).** Это влияет на форматы банковских выписок (парсеры будут под европейские банки, не российские), формат чисел/дат в UI и на то, что мультивалютность в MVP не нужна.
- **Тонкий клиент + сервер.** Вся бизнес-логика и БД — на бэкенде (Python/FastAPI + Postgres), развёрнутом на VPS пользователя. Android-приложение — интерфейс, который ходит в API по HTTPS.
- **Мульти-устройства:** сейчас только телефон (Samsung Galaxy S25), но архитектура должна допускать веб-доступ позже (тот же API, просто ещё один клиент).
- **Источники данных:** ручной ввод + импорт PDF-выписок банков. Прямая интеграция с банковскими приложениями не рассматривается (нет открытого personal-API у большинства банков для частных лиц). Если у банка есть экспорт в CSV/Excel — предпочтительнее PDF, парсить проще и надёжнее.
- **Банки/форматы парсеров:** пользователь предоставит образцы выписок на этапе создания парсеров (парсер под каждый банк делается индивидуально, конкретные банки пока не названы).
- **Категоризация трат по названию торговой точки (зафиксировано):** для MVP — словарь ключевых слов + самообучение на правках пользователя. ML/LLM-подсказка для неизвестных мерчантов отложена на этап после MVP.
- **Учебная цель:** пользователь хочет не только получить готовый результат, но и разобраться самостоятельно в разработке Android-приложения и в деплое — по этим темам двигаемся маленькими шагами с объяснениями и согласованием на каждом шаге.

## Компоненты системы

1. **Backend (VPS):** FastAPI + Postgres, HTTPS (Caddy/Nginx + certbot), JWT-авторизация. Хранит категории, транзакции, счета/банки, импорт-сессии, правила категоризации. Суммы — в евро.
2. **Android-приложение (тонкий клиент):** Kotlin + Jetpack Compose. Экраны: отчёт по категориям за период (список + диаграмма), список транзакций, ручной ввод, импорт PDF (загрузка → бэкенд парсит и категоризирует → превью/правка → подтверждение).
3. **Импорт-пайплайн:** endpoint загрузки PDF/CSV → парсер конкретного банка (pluggable, добавляется по мере получения образцов) → извлечённые транзакции проходят автокатегоризацию → возвращаются на превью перед сохранением.
4. **Автокатегоризация по названию торговой точки (на бэкенде):**
   - Нормализация строки мерчанта (верхний регистр, убрать цифры/коды терминала, убрать юридические суффиксы/префиксы).
   - Проверка личных правил пользователя (таблица «нормализованный мерчант → категория», приоритет выше общего словаря) — заполняется автоматически из правок пользователя при импорте.
   - Проверка общего словаря ключевых слов (сети магазинов, транспорт, подписки и т.п.) — начальный набор строится по факту первых образцов выписок европейских банков.
   - Если не нашли — категория «Без категории», пользователь назначает вручную в экране превью импорта; выбор сохраняется как новое личное правило.
   - ML/LLM-fallback для неизвестных мерчантов — сознательно не в MVP, кандидат для следующей итерации.
   - При наличии CSV-экспорта банка стоит проверить, не размечены ли траты категориями/MCC самим банком — тогда можно смаппить готовые категории вместо собственной классификации.
5. **Веб-доступ (позже):** простой веб-фронтенд, использующий тот же API — добавляется после того, как мобильное приложение и бэкенд стабильны.

## Фазы разработки

1. Дизайн модели данных и API-контракта: транзакции, категории, счета, импорт-сессии, правила категоризации, авторизация. **(текущий шаг, идём по нему пошагово с согласованием)**
2. Скелет бэкенда: FastAPI + Postgres, деплой на VPS, HTTPS, JWT.
3. Основные API-эндпоинты: CRUD категорий и транзакций, агрегация/отчёты по категориям и периодам.
4. Android-клиент: логин, экран отчётов, список транзакций, ручной ввод — всё через API.
5. Импорт-пайплайн: загрузка PDF, парсер под первый банк (по образцу от пользователя), автокатегоризация (словарь + личные правила), превью и подтверждение импортированных транзакций.
6. Сквозное тестирование на реальном S25.
7. (Позже) веб-фронтенд на том же API; рассмотреть ML/LLM-fallback для категоризации неизвестных мерчантов.

## Открытые вопросы / ждём от пользователя

- Образцы PDF-выписок банков (можно с зачищенными персональными данными) — нужны для написания парсеров и начального словаря категорий на шаге 5.
- Уточнить, есть ли у используемых банков экспорт в CSV/Excel в личном кабинете, и размечены ли там траты категориями/MCC самим банком.
